# 通用异常首轮问答模板

下一步：先请用户提供“页面、动作、时间、状态码或第一句错误”，不要先索取日志全文。

## 首轮只问六件事

1. 在哪个模块、哪个页面？
2. 点了什么按钮，或正在执行什么动作？
3. 是打不开、保存不了、生成失败、播放失败、下载失败，还是恢复后缺数据？
4. 页面上的完整状态码或第一句错误是什么？
5. 最小测试是否成功：短文本、单张小图、短音频或一个测试条目？
6. 这是一直如此，还是换模型、导入文件、更新、美化、插件、换设备或清理数据后才出现？

这六项足以把问题先分到：本地界面与存储、浏览器权限与网络、外部 API、任务队列、数据归属，或正常功能边界。

## 状态码快速分流

- 没有状态码、状态码 0、Failed to fetch：先查网络、DNS、TLS、CORS、代理和混合内容。
- 400/422：请求字段、模型、消息结构或参数范围不符合服务要求。
- 401/403：Key、权限、账号、项目或模型授权。
- 402：外部服务余额、套餐或项目额度。
- 404/405：地址、接口路径或请求方法。
- 408/499：请求被服务端或客户端提前取消/超时。
- 409：重复任务或状态冲突，先查询原任务。
- 413/414/415：请求太大、网址太长或文件格式/媒体类型不支持。
- 429：限速、并发或额度策略；停止重复点击后等待。
- 500/502/503：服务端、代理或上游故障。
- 504/524：网关或 CDN 等上游超时。
- 520–526：CDN 与源站、DNS、连接或证书问题。
- HTTP 200 仍失败：检查 Content-Type、空响应、HTML 错误页、流式格式和安全过滤。

## 按失败阶段分流

### 页面打不开、白屏、按钮无反应

先停用最近的美化 CSS 或插件，切回默认主题，降低性能模式；不要先清站点数据。

### 设置、角色或内容刷新后丢失

先导出当前可见数据，检查是否保存到错误角色/预设，再看 IndexedDB、存储配额和隐私模式。禁止用清缓存重装覆盖现场。

### 模型没有回复

用同一线路的新测试会话发送“你好”，区分线路完全不可用、旧会话上下文过长、流式断开或内容过滤。

### 图片、语音、音乐或视频失败

先确认它使用的独立 Provider。主聊天成功不能证明生图、STT、TTS、网易云、原创音乐或实时视频已配置。

### 任务一直处理中

先查询原任务状态，不要重复创建。记录任务类型、创建时间和脱敏 ID 后四位。

### 导入、恢复或换机后异常

停止继续覆盖；保留原备份和恢复前备份。确认使用的是完整格式而非只含文字的导出。

### 内容串到错误角色或越过可见范围

这是高优先级问题。停止自动生成/同步，记录目标角色与实际角色，用占位符代替正文，立即升级开发者。

## 安全日志格式

建议用户只提供：

```text
应用版本：
平台/浏览器/PWA：
模块和页面：
操作步骤：
发生时间：
状态码或错误名：
响应第一句：
最小测试结果：
最近一次相关改动：
```

必须遮挡：API Key、Authorization、Cookie、Token、完整私有地址、聊天正文、角色提示词、世界书、日记、账本、精确位置、真人图片、录音和备份内容。

## 不要给出的高风险建议

- 不要把“清除站点数据、清空数据库、重装”作为首轮排查。
- 不要让用户把所有 API 都换掉或同时修改多个设置。
- 不要让用户公开完整 Network 请求、请求体或响应正文。
- 不要把外部服务的 401、429、5xx 说成眠眠机本地数据损坏。
- 不要把页面“导出成功”当成备份完成；必须在系统文件管理器核对文件存在和大小。
- 不要在任务状态未知时让用户重复点击生成、支付、上传或恢复。
